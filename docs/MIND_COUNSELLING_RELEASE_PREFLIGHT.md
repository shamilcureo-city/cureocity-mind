## Rollback is not simply restoring old main

After new records exist, old code lacks the new manual-session recording/AI boundaries and the new-table export/erasure handling. Client erasure is a soft delete, so foreign-key cascades do not make an old application safe. Retain the new privacy/authority/read-compatibility paths in any rollback build, along with the additive tables and reminder unique index. Prefer a compatible feature rollback or forward fix. Do not drop clinical records or reset migration history.

Release remains on hold until the operational and clinical gates above are explicitly resolved.
